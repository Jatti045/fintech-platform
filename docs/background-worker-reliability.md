# Background worker reliability

The checked-in Fly configuration keeps one worker-capable `app` Machine running in the primary region (`sin`) when HTTP traffic drops. Fly Proxy can still stop surplus Machines. The floor applies to existing Machines in the primary region. When activating this configuration in a later release, confirm the app has a running Machine there. One continuously running 1 GB Machine incurs compute charges even while idle. See [Fly autostop configuration](https://fly.io/docs/launch/autostop-autostart/) and [regional compute pricing](https://fly.io/docs/about/pricing/).

Monitor the aggregate Plaid sync and revocation logs for due jobs and oldest due age. Profile image cleanup logs report pending jobs, due jobs, and oldest pending age. Sustained age growth warrants checking worker availability, database connectivity, and provider configuration. Queue leases allow another process to recover abandoned work. One Machine is an idle capacity floor and provides no redundancy during a Machine or regional outage.

Profile image changes and account deletion commit obsolete asset IDs to PostgreSQL with the reference change. The scheduler retries outside the request and database transaction. Cloudinary confirmation or an already-absent response clears the job. Each upload uses a fresh, non-overwriting ID. The worker excludes assets still referenced by an account. If a process dies after upload but before the reference or compensation commits, an operator may need to reconcile the orphan in Cloudinary. Existing accounts with a URL but no stored public ID cannot be cleaned up automatically.
